  <files>frontend/src/lib/api.ts</files>
  <action>
    In the `apiPost` function, replace the simple error throw with a try/catch that attempts to read the response body:

    Before:
    ```typescript
    if (!res.ok) {
      throw new Error(`API error: ${res.status}`)
    }
    ```

    After:
    ```typescript
    if (!res.ok) {
      try {
        const body = await res.json()
        throw new Error(body.detail || `API error: ${res.status}`)
      } catch {
        throw new Error(`API error: ${res.status}`)
      }
    }
    ```

    How this works:
    - If the error response has a JSON body with a `detail` field (standard FastAPI HTTPException format), that message is surfaced
    - If `body.detail` is undefined/falsy, falls back to "API error: {status}"
    - If `res.json()` fails entirely (non-JSON body), the outer catch re-throws with the status code fallback

    IMPORTANT: The inner catch handles BOTH the case where res.json() fails AND the case where the first throw propagates. The first `throw new Error(body.detail || ...)` will be caught by the catch block. To handle this correctly, use this pattern instead:

    ```typescript
    if (!res.ok) {
      let message = `API error: ${res.status}`
      try {
        const body = await res.json()
        if (body.detail) {
          message = body.detail
        }
      } catch {
        // Response body not parseable as JSON, use status code fallback
      }
      throw new Error(message)
    }
    ```

    This avoids the re-catch problem: first try to extract the detail, then always throw with whatever message we have.

    Do NOT:
    - Modify `apiGet` (the 429 spending cap only occurs on POST /api/compare; apiGet has no spending-cap scenario)
    - Create error type hierarchies or custom error classes (one try/catch is sufficient)
    - Add error parsing middleware or interceptors
    - Change the API_BASE constant or any other part of the file
  </action>
