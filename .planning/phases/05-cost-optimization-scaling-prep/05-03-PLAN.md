5. Add comparison deduplication in `backend/app/routers/comparison.py`:

In `submit_comparison()`, AFTER the spending cap check and BEFORE creating the background task, add dedup logic:

```python
import hashlib

# Dedup: check if identical comparison was run in last 24h
if not force_refresh:
    dedup_key = hashlib.sha256(
        f"{data.option_a.lower().strip()}|{data.option_b.lower().strip()}|{data.intent.lower().strip()}".encode()
    ).hexdigest()[:16]
    # Check existing results for a match
    existing_results = storage.list_results()
    for existing in existing_results:
        existing_key = hashlib.sha256(
            f"{existing.option_a_name.lower().strip()}|{existing.option_b_name.lower().strip()}|{existing.intent.lower().strip()}".encode()
        ).hexdigest()[:16]
        if existing_key == dedup_key and existing.status == "completed":
            # Check if result is less than 24h old
            from datetime import datetime, timezone, timedelta
            created = datetime.fromisoformat(existing.created_at)
            if datetime.now(timezone.utc) - created < timedelta(hours=24):
                return {"comparison_id": existing.comparison_id, "deduplicated": True}
```

This returns the existing comparison_id instead of starting a new one. The frontend already handles navigating to a comparison_id, so this works transparently.

Note: The spending guard `add_cost()` wiring is handled in Plan 01 — `record_usage()` calls `add_cost()` automatically. The `check_spending_cap()` call here is a pre-flight check only. It checks the accumulated daily cost so far and rejects if already over. It does NOT reserve budget for the upcoming request.

Add a helper function at the top of the file (outside the component):
```typescript
function formatCacheAge(cachedAt: string): string {
  const cached = new Date(cachedAt)
  const now = new Date()
  const diffMs = now.getTime() - cached.getTime()
  const diffHours = Math.floor(diffMs / (1000 * 60 * 60))
  const diffMinutes = Math.floor(diffMs / (1000 * 60))

  if (diffHours >= 1) {
    return `${diffHours}h ago`
  }
  return `${diffMinutes}m ago`
}
```

Important: The refresh button submits a new comparison with `force_refresh=true`. This is the simplest approach — it creates a new comparison entry rather than mutating the existing one. The user is redirected to the new result.

Design choice: `window.location.reload()` is used intentionally here rather than TanStack Query invalidation. The refresh creates an entirely new comparison_id (different URL hash), so the page needs a full navigation to pick up the new comparison. This is equivalent to the user submitting a new comparison from the form — not a cache invalidation of the current query.
